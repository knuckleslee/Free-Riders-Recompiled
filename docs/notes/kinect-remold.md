Free Riders 用的微軟 SDK 1.8 / 2.0 就看不到感應器了。它還會把自簽憑證裝進本機的受信任根憑證和受信任發行者。

## 1. 關節被遮住時的處理（webcam 姿勢，最值得）

Free Riders 現況：`src/pose_smoothing.cpp` 只有 1 Euro 濾波器，負責去抖動。

Remold 的做法（見它的 `docs/SKELETON-3D-ARCHITECTURE.md` 和 README 的 Interactivity and Body3D 一節）：

- **短暫遮住時用預測補上：** 依各關節的速度和骨架連動推估位置，信心值逐格下降。
  要等到有符合身體部位的新觀測，才恢復成「量到的」。
- **骨長限制：** 依使用者的軀幹長、肩寬、髖寬和四肢比例，固定各段骨長。
  一格內骨頭忽然變長、或手跳到另一側，就當成誤判丟掉。
- **加速度上限：** 單格的突跳不採用。
- **左右側和區域鎖定：** 手肘、手腕、手只接受同一側、符合身體區域的觀測。
  下半身的點不會只因為畫面位置剛好疊到放低的手，就被當成手。
- **深度分層：** 手臂經過軀幹前方時，用相對軀幹的深度分開。這一項 webcam 沒有深度，只能借概念；
  Kinect v1 的深度可以用。

對 Free Riders 的好處：比賽中手臂交叉或擋到身體時，比較不會誤觸動作或突然轉向。

## 2. 游標和骨架分開濾波（選單）

- 骨架照原樣送給遊戲，游標另外濾波。
- 接近靜止時用比較大的靜止死區，去掉微小抖動。
- 刻意移動時用自適應平滑，提高反應速度。
- 用加速度和速度上限擋掉單格的追蹤突跳。
- 按下、放開、拖曳、雙擊、捲動等手勢，仍然依「手和軀幹的距離」判斷，不受游標平滑延遲。

Free Riders 現況：游標也走 1 Euro 濾波器。可以加上「靜止死區」和「突跳過濾」。

## 3. Kinect v1 自動俯仰

Free Riders 現況：`kinect_sensor_win32.cpp` 有 `NuiCameraElevationSetAngle`，只能手動調整。

Remold 的做法（見它的 `docs/MOTION.md`）：

- 用臉部追蹤自動調整馬達。
- 以加速度計回饋，加上指令頻率限制、死區和等待馬達穩定。
- 沒有程式在用畫面時，馬達不動。

可以借成：開始前自動對準，讓全身入鏡；比賽中不要動，馬達會讓畫面晃。

## 4. 「實際可用」才算準備好

Remold 的安裝檢查，是確認每項功能實際能用才顯示 READY，不是看服務裝了沒（見它的 `docs/UNIFIED-DEVICE-CONTRACT.md`）。

可以借到 Free Riders 的 Kinect 預覽，分層告訴玩家卡在哪一步：

1. 找不到 SDK；
2. 找不到感應器；
3. 有影像，但沒抓到骨架。

這一點還沒確認啟動器現在顯示到多細。

## 不值得或太大

- **Linux 實體 Kinect：** Free Riders 目前只支援 Windows。Remold 證明 Linux 用 libusb 可行，
  但難在沒有微軟 SDK，骨架要自己從深度圖算。真要做，應該拿 libfreenect 當基礎。
- **3D 掃描、監視器、麥克風陣列、IP 攝影機：** 和遊戲無關。
